### Backend findings — reported, **not changed** (business rules / need real data)

All **[static]**: read from code, not run against SQL Server.

* **H1 — "Met" may never be persisted on a real DB.** `ResolveAsync` evaluates `SlaBreachProcessor` before `SaveChanges`; `GetAchievementMomentAsync` reads the resolution through a plain DB query, which does not return the unsaved row, so `MarkSlaMet` is skipped and an on-time resolved ticket may keep `SlaState = Running`. The test fake returns unsaved rows, so unit tests pass. The redesigned page does not depend on it (a finished, un-breached ticket shows "Met"), but reports/lists reading `SlaState` would. *Needs an EF/SQL integration test and a production query (`Tickets` Resolved/Closed with `SlaState = Running`).*
* **H2 — first-response backdating.** `RecordFirstResponse` accepts a caller-chosen `Source` (including undefined numbers) and applies the "not before ticket creation" bound only for `Manual`; the Genesys path picks the first human message by `Sequence`, not time, with no future bound.
* **H3 — Escalate has no ticket-visibility check** for CS-layer callers (compare `PriorityDowngradeAppService`, which applies the agent scope).
* **M1 — sticky `Breached`** stays after a reopen while both new-period flags are clean; `BuildExplanation` then says "The Resolution deadline was missed" for the new cycle.
* **M4 — Close**: the server rejects a previous owner who can no longer follow department work, even for supervisors; the UI shows Close (403).
* **M5/M6 — customer lookup**: a CRM *failure* is not persisted (only an audit string), so it is indistinguishable from "not found"; `PendingCrmVerification` is effectively dead; PACT/Tasleeh customer names are not on `TicketDetailDto`; a Genesys placeholder name can overwrite the looked-up name.
* **M7 — owner name** is resolved by paging the current department's *active* users (2×100); a deactivated/other-department owner shows "Employee #xxxxxxxx". The Api resolves `FirstHandledByName` but not the current owner's.
* **L1/L2 — timeline**: "SLA state changed Running → Running" by System after a manual first response; same-instant ordering ranks assignment before "reopened/resolved"; some Genesys events can precede "Ticket created"; no first-response event.
* **L3** `POST /sla/first-response` returns a summary without pause/explanation; **L4** `Classify` on a ticket whose request type is already set throws (500) on a direct API call; **L5** `CustomerNameValidator` is whole-string only; **L6** SLA notes embed UTC (`:u`).

## 2. What changed

Information architecture (top to bottom): **Header** (number, subject, status, priority, SLA, assigned to/department, *Actions* menu) → **Customer summary** → **Next step** (one gold action, ≤2 blockers, "Not available to you" fold, "Record first response" when allowed) → tabs. **Overview**: request details + "Handled by" → conversation (AI/human, handoff, call facts, transcript, empty states) → satisfaction (only when a review exists) → latest 3 activities (full timeline = Activity tab) → **Additional details** (collapsed): SLA per clock, verification & unit, handling & escalation, workflow, reviews/approvals/attachments, audit-history link.

Unchanged by design: every handler/endpoint, all permission gates (except #8/#11, tightened to match the server), status transitions, request-type/classification rules, Genesys contracts, verification rules, role sets.

## 3. Verification

* Full solution build and test run: see the PR description for the final numbers.
* New: `TicketDetailsRedesignUnitTests` (SLA not started/running/paused/stopped/missed/reopened, nearest-deadline and past-due badge, customer states incl. registered, external, unregistered, CRM failure, manual, none; owner label; record-first-response role matrix; call facts) and `TicketDetailsRedesignRenderTests` (unclassified, classified-unassigned, assigned, AI-only, human handoff, phone call, CRM failure, resolved, closed, reopened, paused; CS Agent / CS Manager / Reporting User; one-gold-action and no-duplicate-owner assertions).
* Existing assertions in seven test files were updated because they pinned the removed structure (Quick-facts aside, "What needs your attention?" label, Customer card, Attachments tab, "Current owner"/"Resolved on" rows, always-visible empty satisfaction).
* Layout: Chromium at 1280 px and 390 px, six scenarios, zero horizontal overflow; screenshots in `docs/ticket-details-screenshots/redesign/`.

## 4. Unresolved — need production data or environment access

1. H1: count Resolved/Closed tickets whose `SlaState` is still `Running`; confirm with an EF + SQL Server test.
2. Server time zone of the Web host (the old `ToLocalTime()` bug only mattered if it is not UAE) and the real behaviour of the breach-detection job interval (window in which an overdue SLA is not yet flagged — now shown as "past due").
3. How often CRM lookups fail in production vs return "not found" (not persisted; cannot be told apart).
4. Real Genesys payloads: whether `Direction`, `GenesysQueueName` and end reasons are populated for phone calls and WhatsApp.
5. Whether `EscalationCount` includes automatic SLA escalations (the label no longer claims a reason, but the count semantics were not verified).
6. Business decisions for H2/H3/M1/M4 and a screen-reader/keyboard pass with real assistive technology (only automated layout checks were run).
